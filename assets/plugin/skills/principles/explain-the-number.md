# Explain the number

Before trusting a number, explain it.

- Write down the result that would change your decision, and the noise floor.
- Name what limits the number (why isn't it double?), from a profile or counters, not a guess.
- Rule out what else it could be measuring: errors, skipped or cached work, code that never
  ran, an untuned side, noise.
- Keep the run count, the spread and the limiter with the number.
